# Добавление композиции

Новая композиция должна описывать форму, направления и границы появления/исчезновения. Сам плеер копировать не нужно.

## Из шаблона

1. Скопируйте `docs/templates/composition.json` в `src/compositions/my-composition.json`.
2. Задайте уникальный `id` латиницей и понятный `title`.
3. Укажите `viewBox: [width, height]`, стиль и вершины исходной ломаной в `basePath`.
4. Для каждой вершины задайте одну стрелку. Её `from` должен совпасть с этой вершиной, `to` — с конечной точкой её движения.
5. Добавьте импорт JSON и элемент в массив `compositions` файла `src/compositions/registry.js`.
6. Запустите `npm test` и `npm run build`, затем проверьте несколько циклов в предпросмотре и выгруженном SVG.

```js
// src/compositions/registry.js
import myComposition from './my-composition.json' with { type: 'json' };
export const compositions = [rostFold, corridor, chevron, myComposition];
```

Минимальный смысл одной стрелки:

```json
{
  "id": "center-flow",
  "vertex": 1,
  "from": [960, 60],
  "to": [960, 690]
}
```

```text
basePath[1] = [960, 60]  ● начало
                        │
                        │ направление и длина траектории
                        ▼
                  [960, 690] конец
```

Настройка `secondsPerStep` меняет время прохождения одного промежутка между линиями. Для плотности используется `lineCount`, для ускорения и распределения промежутков — `perspective`. Если конечные точки остаются в кадре, задайте `motion.fadeOut > 0`; валидатор отклонит попытку сделать видимый скачок без затухания.

## Из Figma или изображения со стрелками

Передайте Codex точную ссылку на узел и изображение с направлениями. Укажите, где линия появляется и где выходит/исчезает. Если разные части ломаной движутся по-разному, нужна отдельная стрелка у каждого излома.

Пример задания:

> Добавь эту композицию в motion lab. Сохрани форму и цвета указанной ноды Figma. Белые стрелки показывают направление движения изломов. Создай JSON версии 1, проверь правильность from/to, отсутствие противоречивых стрелок и бесшовность цикла. Стрелки нужны только в редакторе, в финальный SVG не входят.

Изображение со стрелками не загружается в движок как готовая анимация. Codex читает референс, извлекает векторную геометрию из Figma/SVG или вручную описывает точки, сопоставляет стрелки с вершинами и сохраняет JSON. Если часть движения неоднозначна, это нужно разрешить до подбора анимации.

Для уже нарисованного повторяющегося паттерна используйте `sampled-rows`: все `rows` должны содержать одинаковое число точек в одинаковом порядке. Один и тот же индекс соответствует одной траектории. Стрелки задают общий проход по рядам. Обратные стрелки допустимы, противоположные указания внутри одной композиции — ошибка. Этот режим сохраняет сложную исходную геометрию; перетаскивание стрелки не должно превращаться в неявное изменение формы.

## Проверка перед передачей

- Первый, средний и последний видимые ряды совпадают с задуманной формой.
- Каждая вершина идёт в сторону своей стрелки; инверсия обращает весь поток.
- Новая линия появляется плавно, уходящая скрыта до смены индекса.
- Видимый набор линий совпадает в начале и конце шага в обоих направлениях.
- Пауза, скорость, stroke и reduced motion продолжают работать.
- В самостоятельном SVG нет стрелок редактора, внешних картинок или временных Figma URL.

При добавлении принципиально другого класса движения расширяйте `motion.mode` и валидатор с тестами. Не добавляйте условия по `composition.id` в плеер: имя композиции не должно определять её математику.
