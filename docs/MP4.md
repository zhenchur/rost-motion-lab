# Экспорт MP4

MP4 строится из кадров общей motion-модели. Каждый SVG-кадр растеризует resvg, затем FFmpeg кодирует H.264 с `yuv420p` и `faststart`. В записи нет браузерного интерфейса, разметки референса, курсора или просадок FPS живого предпросмотра. Движение, настроенное Codex по скриншоту со стрелками, инверсия, скорость, толщина и плотность линий учитываются одинаково с предпросмотром.

## Интерфейс

Запустить `npm ci`, затем `npm run dev`. Кнопка MP4 отправляет выбранную композицию локальному серверу; после завершения можно скачать файл. API работает также с `npm run preview`, если этот script присутствует в package.json.

Автономный HTML и обычный статический хостинг не выполняют Node.js/FFmpeg. Для MP4 используйте локальный сервер проекта или команду ниже. SVG продолжает экспортироваться без сервера.

## Командная строка

```sh
npm run export:mp4 -- --composition rost-fold --output artifacts/rost-fold.mp4
npm run export:mp4 -- --composition rost-fold --output artifacts/rost-reverse.mp4 --density 1.5 --inverted --duration 6 --fps 60
npm run export:mp4 -- --composition ./my-composition.json --output artifacts/custom.mp4 --width 4 --seconds 2
```

ID реальной композиции и её внутренний файл создаёт Codex при реализации. Путь к JSON в третьей команде — возможность CLI для разработчика, а не требование к пользователю готовить данные.

`--density` задаёт плотность от `0.5` до `2`, по умолчанию `1`: меньшее значение делает линии реже, большее — чаще. Геометрия и толщина линий сохраняются. Время шага по умолчанию равно `secondsPerStep / плотность`, поэтому изменение плотности сохраняет скорость движения вдоль траектории.

`--seconds` явно задаёт итоговое время одного шага между линиями. Экспорт не делит это значение на плотность повторно. Интерфейс передаёт `secondsPerStep / плотность / скорость`; например, при исходных `1.5` секунды, плотности `1.5` и скорости `1` цикл равен `1` секунде. `--width` — толщину обводки, не ширину видео. `--duration` — желаемую минимальную длительность. Фактическая длительность округляется вверх до целого числа циклов. Время одного цикла квантуется до ближайшего целого числа кадров; погрешность не более половины кадра. Последний кадр соответствует моменту перед началом следующего цикла и не дублирует первый.

По умолчанию: 30 FPS и не менее 6 секунд. Допустимо 12–60 FPS и до 30 секунд итогового видео. Размер сохраняет пропорции композиции в пределах 1920×1080 без увеличения маленьких исходников. При нечётном размере FFmpeg добавляет до одного пикселя фона справа/снизу для совместимости с `yuv420p`: исходная композиция РОСТ 1920×793 даёт MP4 1920×794. В MP4 нет прозрачности и аудио.

Существующий файл не заменяется без `--overwrite`. Временный файл переносится на конечный путь только после успешного кодирования.

Если при выбранной скорости на цикл приходится меньше двух кадров, экспорт попросит увеличить FPS или уменьшить скорость. Это предотвращает превращение короткого движения в неподвижное видео.

## Перенос

`npm ci` устанавливает нативный resvg и FFmpeg для текущей ОС. Не копируйте `node_modules` с другой машины. Для загрузки зависимостей при установке нужен интернет; само кодирование работает локально. Поддержка платформ зависит от доступных бинарных сборок [resvg-js](https://github.com/thx/resvg-js) и [ffmpeg-static](https://github.com/eugeneware/ffmpeg-static). Установка и реальный экспорт проверяются командой `npm run test:mp4`.

## Локальный API

- `POST /api/exports/mp4` с `{ composition, options: { width, density, seconds, inverted, fps, duration } }` → `202 { jobId, statusUrl, downloadUrl }`.
- `GET statusUrl` → `{ status, progress, metadata?, error? }`.
- `GET downloadUrl` → готовый `video/mp4`.

Одна задача за раз. JSON ограничен 1 MiB, экспорт — 30 секундами / 1800 кадрами и пятью минутами обработки. Завершённые задачи хранятся до 30 минут; результаты находятся в игнорируемом `.exports`. Обработчик принимает запросы только от loopback и того же origin. Это локальный инструмент; для публичного серверного экспорта нужен отдельный сервис с авторизацией, очередью и квотами.

Параметры MP4-контейнера описаны в [официальной документации FFmpeg](https://ffmpeg.org/ffmpeg-formats.html#mov_002c-mp4_002c-ismv).

## Проверено при подготовке

На Windows, Node.js 24.12.0: настоящий MP4 H.264/yuv420p 1920×794, 12 FPS, 36 кадров / 3 секунды, плотность `1.5`, обратное движение. FFmpeg полностью декодировал файл; длительность и число кадров совпали с планом; `moov` расположен перед `mdat` (`faststart`). Исходные растровые кадры повторяются побитово через полный цикл, последний кадр не дублирует первый. Дополнительно проверены 36 совпадений кадров модели, статичного/анимированного SVG и MP4: плотности `0.5`, `0.75`, `1`, `1.25`, `4/3`, `2`, оба направления. Неверная плотность отклоняется; явное время цикла применяется без повторного деления. Проверки включены в `npm run test:mp4`.

При предыдущей проверке базового локального API подтверждены: создание задачи `202`, блокировка чужого Origin `403`, параллельного экспорта `409`, успешный статус и скачивание MP4 с реальной сигнатурой `ftyp` (18 кадров / 1,5 секунды). При добавлении плотности браузер и HTTP API не проверялись; текущая проверка выполнялась напрямую через функции экспорта и FFmpeg. macOS и Linux в этом запуске не проверялись.
