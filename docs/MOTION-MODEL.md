# Модель движения линий

Это внутренний контракт для Codex и разработчика. Пользователь передаёт чистый паттерн и скриншот со стрелками; Codex сам извлекает векторы из Figma и готовит данные композиции. JSON не является пользовательским редактором или обязательным входным материалом.

Композиция — JSON с геометрией, стилем и числовым описанием движения. Чистый модуль `src/motion/model.js` строит геометрию и SVG; плеер управляет временем, паузой и инверсией. Новые реальные композиции не требуют копирования плеера.

```text
Чистая Figma → геометрия   РОСТ → стиль   Скрин со стрелками → движение
                    ↓ интерпретация и реализация Codex
             composition.json, version: 1
                    ↓ validateComposition
            createMotionModel(composition)
                    ↓
  pointsAt / pathAt / opacityAt → SVG-плеер
                    ↓
          статичный / анимированный SVG / MP4
```

Стрелки на изображении интерпретирует Codex, сопоставляя их с чистым паттерном с учётом кропа и масштаба. Внутренние `from`/`to` описывают рассчитанное движение; длина рисованной стрелки не становится точной длиной траектории или скоростью без явного указания. Стрелки не отображаются в плеере и экспортах. Порядок работы описан в [NEW-COMPOSITION.md](NEW-COMPOSITION.md).

Геометрия сохраняет характерные изломы, пропорции и кадр нового макета, а оформление и интервалы наследуются от первого РОСТ через `src/motion/pattern-profile.js`: настоящая обводка с `fill="none"` и `stroke-linejoin="miter"`; базовые настройки `#dd192d`, opacity `0.6`, ширина `3`, фон `#1a1d24`. Заполненные полосы преобразуются в осевые пути, а не обводятся по внешнему контуру.

## Общий профиль РОСТ

`ROST_STYLE` и `ROST_MOTION` берутся из `rost-fold.json`. Реестр подключает один объект `ROST_STYLE` ко всем композициям; значения стиля в JSON сохраняются для самостоятельного использования через CLI. `ROST_SPACING` содержит 26 накопленных расстояний `s[0] = 0`, `s[i] = s[i−1] + hypot(rows[i][28] − rows[i−1][28])` вдоль исходного излома с индексом 28. Это точные значения из первого паттерна, а не заново подобранная кривая перспективы. При добавлении композиции их не масштабируют под её длину, размеры или желаемое число рядов. Для продолжения за последний уровень `nextSpacingGap` повторяет исходный последний интервал `80.88056979254532` единицы viewBox.

Новые ряды размещаются по этим расстояниям вдоль соответствующей траектории излома новой формы. Это мера вдоль потока: перпендикулярный экранный зазор зависит от наклона сегментов, поэтому одинаковые расстояния профиля не означают пиксельно равные зазоры во всех частях композиции. По умолчанию используется перспективное увеличение интервалов первого РОСТ; переход к равномерному шагу — отдельное изменение по запросу пользователя.

`rost-fold` сохраняет всю исходную геометрию Figma 2170:664. Для `rost-fan` источником формы служит [Figma 2179:1529](https://www.figma.com/design/RnBHxdFLuCb2eIb6NTBCap/?node-id=2179-1529); `scripts/build-rost-fan.mjs` преобразует её векторные пути в осевые ряды и применяет общий профиль. Нормализация интервалов новой композиции не меняет первую.

## Два режима геометрии

| Режим | Источник формы | Что определяют стрелки | Когда использовать |
| --- | --- | --- | --- |
| `sampled-rows` | Все готовые ряды `rows` с одинаковым числом вершин | Общее направление прохода по исходным рядам | Уже нарисованный повторяющийся паттерн, который нужно сохранить |
| `arrow-field` | Одна исходная ломаная `basePath` | Траекторию каждой вершины от `from` до `to` | Внутренний расчёт подходящего реального паттерна по интерпретации Codex |

`rost-fold.json` содержит все 26 × 36 осевых точек исходного макета. Монотонная кубическая интерполяция проходит через исходные ряды без изменения их координат. Шаг 1,5 секунды и прежняя форма сохранены. Промежуточные точки проверяются относительно первоначальной геометрии; её эталон хранится в `scripts/fixtures/rost-v1-geometry.js`. `src/geometry.js` — совместимый адаптер общего движка.

В `sampled-rows` каждая стрелка имеет `vertex`. Её вектор сравнивается с направлением перемещения этой вершины от первого до последнего ряда. Если все стрелки направлены вдоль движения, `model.direction = 1`; если против, `-1`. Противоречивые стрелки или почти перпендикулярный вектор отклоняются с ошибкой. Изменение стрелки здесь не деформирует исходную геометрию.

В `arrow-field` для каждой вершины нужна ровно одна стрелка. `from` совпадает с `basePath[vertex]`, `to` задаёт конечную точку. Номер вершины отсчитывается от нуля. Движение вычисляется так:

```text
p = depth / lineCount
q = p / (perspective − (perspective − 1) × p)
point = from + (to − from) × q
```

При `perspective = 1` ход равномерный. Большие значения увеличивают расстояния между линиями и их экранную скорость к концу траектории. `model.direction = 1`, потому что направления уже заданы индивидуальными векторами. Инверсия плеера меняет проход всех траекторий одновременно.

Это параметрическая модель перспективного движения ломаных, а не калиброванная физическая 3D-камера. Направления вниз, вверх или вбок задаёт Codex по скриншоту. Сильное пересечение траекторий может создавать самопересекающиеся линии — внешний вид проверяется в предпросмотре. Если сохранение нового паттерна требует другого класса движения, нужно расширить общий движок с проверкой, а не упрощать исходную форму под этот режим.

## Время и бесшовность

Каждая линия имеет глубину `i + phase`, где `i = 0…lineCount−1`, а `phase` пробегает один шаг. В конце шага каждая линия совпадает с начальным положением соседней. Период изображения равен `secondsPerStep`; это время движения между соседними рядами, а не время прохода одной линии через всю композицию.

`fadeIn` и `fadeOut` измеряются в шагах рядов, а не в секундах. Прозрачность изменяется по smoothstep с нулевой производной на концах. В начале пути opacity равна нулю. В конце линия должна либо полностью покинуть кадр, либо иметь `fadeOut > 0`. При нулевом `fadeOut` проверяется выход в одну общую полуплоскость за границами viewBox с запасом для обводки. Это исключает ситуацию, когда вершины находятся снаружи, а соединяющий их сегмент пересекает кадр.

Для исходного РОСТ `fadeOut = 0`, потому что последний ряд уже целиком ниже кадра. Для нового паттерна Codex выбирает выход за границу или затухание согласно референсу. Короткая стрелка, нарисованная внутри кадра, сама по себе не требует останавливать или гасить там линии.

## Публичный API

```js
import { createMotionModel, validateComposition } from './src/motion/model.js';
import { getComposition } from './src/compositions/registry.js';

const composition = getComposition('rost-fold');
validateComposition(composition); // возвращает input, при ошибке выбрасывает Error
const model = createMotionModel(composition);

model.width; model.height;
model.lineCount; model.color; model.background;
model.strokeWidth; model.seconds; model.direction;
model.composition;                 // снимок входных данных
model.pointsAt(3.4);               // [[x, y], ...]
model.pathAt(3.4);                 // открытый SVG path
model.opacityAt(3.4);              // число 0…1
model.staticSvg({ phase: .4, width: 3, background: false });
model.animatedSvg({ seconds: 1.5, width: 3, inverted: true });
```

Допустимая глубина — от 0 до `lineCount` включительно. Опция `width` в экспортерах — толщина stroke в единицах viewBox. Опция `original: true` для статичного SVG показывает все исходные линии без маски появления. Для кадра живой анимации используйте обычный `staticSvg({ phase })`.

В анимированном SVG используется SMIL с 40 интервалами на шаг, без скриптов и сетевых зависимостей. Инверсия разворачивает и геометрию, и opacity. `prefers-reduced-motion` переключает экспорт на статичную группу. Размеры корневого SVG сохраняют исходный viewBox, а обводка масштабируется вместе с композицией.

## Валидация и границы

Структура описана в `src/compositions/composition.schema.json` (JSON Schema 2020-12). Runtime-валидатор дополнительно проверяет отношения между полями, геометрию выхода, уникальность и согласованность стрелок. Неизвестные поля версии 1 отклоняются.

- 2–80 линий, 2–128 точек на путь, суммарно не более 8192 точек.
- Размер viewBox — 1–16384; координаты конечны и ограничены ±1 000 000.
- Цвета — только `#RRGGBB`; stroke — 0,25–24 единицы; opacity — 0–1.
- Шаг — 0,1–60 секунд; перспектива — 1–12.
- Все пути открытые, с `fill="none"` и настоящей обводкой.
- Экспортер экранирует заголовок и проверяет числовые параметры; JSON не может добавить исполняемый SVG-код.

`scripts/verify-compositions.mjs` проверяет реальный РОСТ и внутренние синтетические данные для контрактов движка: исходную геометрию, конечность данных, направление, перестановку линий в обоих направлениях, SVG-экспорт и ошибки входных данных. Эти тестовые данные не зарегистрированы как композиции и не являются заготовками приложения.
