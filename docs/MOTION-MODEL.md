# Модель движения линий

Композиция — JSON с геометрией, стилем и стрелками. Чистый модуль `src/motion/model.js` строит геометрию и SVG; плеер управляет временем, паузой и инверсией. Новые композиции не требуют копирования плеера.

```text
Figma / SVG / изображение с нанесёнными стрелками
                    ↓ интерпретация и проверка геометрии
             composition.json, version: 1
                    ↓ validateComposition
            createMotionModel(composition)
                    ↓
  pointsAt / pathAt / opacityAt → SVG-плеер
                    ↓
          статичный / анимированный SVG
```

Стрелки на изображении сначала переводит в числовые `from`/`to` разработчик или Codex. Автоматического распознавания произвольного изображения в движке нет. По картинке нужно отдельно подтвердить привязку каждой стрелки к вершине. Стрелки — инструкции движения и слой редактирования; в выгруженные SVG они не входят.

## Два режима геометрии

| Режим | Источник формы | Что определяют стрелки | Когда использовать |
| --- | --- | --- | --- |
| `sampled-rows` | Все готовые ряды `rows` с одинаковым числом вершин | Общее направление прохода по исходным рядам | Уже нарисованный повторяющийся паттерн, который нужно сохранить |
| `arrow-field` | Одна исходная ломаная `basePath` | Траекторию каждой вершины от `from` до `to` | Новая композиция, которую формируют стрелками |

`rost-fold.json` содержит все 26 × 36 осевых точек исходного макета. Монотонная кубическая интерполяция проходит через исходные ряды без изменения их координат. Шаг 1,5 секунды и прежняя форма сохранены. Промежуточные точки между рядами совпадают с первоначальным модулем `src/geometry.js`; тест проверяет 2601 положение. Старый модуль оставлен как эталон миграции.

В `sampled-rows` каждая стрелка имеет `vertex`. Её вектор сравнивается с направлением перемещения этой вершины от первого до последнего ряда. Если все стрелки направлены вдоль движения, `model.direction = 1`; если против, `-1`. Противоречивые стрелки или почти перпендикулярный вектор отклоняются с ошибкой. Изменение стрелки здесь не деформирует исходную геометрию.

В `arrow-field` для каждой вершины нужна ровно одна стрелка. `from` совпадает с `basePath[vertex]`, `to` задаёт конечную точку. Номер вершины отсчитывается от нуля. Движение вычисляется так:

```text
p = depth / lineCount
q = p / (perspective − (perspective − 1) × p)
point = from + (to − from) × q
```

При `perspective = 1` ход равномерный. Большие значения увеличивают расстояния между линиями и их экранную скорость к концу траектории. `model.direction = 1`, потому что направления уже заданы индивидуальными векторами. Инверсия плеера меняет проход всех траекторий одновременно.

Это параметрическая модель перспективного движения ломаных, а не калиброванная физическая 3D-камера. Стрелки можно направлять вниз, вверх или вбок. Сильное пересечение траекторий может создавать самопересекающиеся линии — внешний вид проверяется в предпросмотре.

## Время и бесшовность

Каждая линия имеет глубину `i + phase`, где `i = 0…lineCount−1`, а `phase` пробегает один шаг. В конце шага каждая линия совпадает с начальным положением соседней. Период изображения равен `secondsPerStep`; это время движения между соседними рядами, а не время прохода одной линии через всю композицию.

`fadeIn` и `fadeOut` измеряются в шагах рядов, а не в секундах. Прозрачность изменяется по smoothstep с нулевой производной на концах. В начале пути opacity равна нулю. В конце линия должна либо полностью покинуть кадр, либо иметь `fadeOut > 0`. При нулевом `fadeOut` проверяется выход в одну общую полуплоскость за границами viewBox с запасом для обводки. Это исключает ситуацию, когда вершины находятся снаружи, а соединяющий их сегмент пересекает кадр.

Для исходного РОСТ `fadeOut = 0`, потому что последний ряд уже целиком ниже кадра. В двух примерах `arrow-field` конечные точки доступны для редактирования в кадре, поэтому используется `fadeOut = 1.5`.

## Публичный API

```js
import { createMotionModel, validateComposition } from './src/motion/model.js';
import { getComposition } from './src/compositions/registry.js';

const composition = getComposition('rost-fold');
validateComposition(composition); // возвращает input, при ошибке выбрасывает Error
const model = createMotionModel(composition);

model.width; model.height;
model.lineCount; model.color; model.background;
model.strokeWidth; model.seconds; model.direction;
model.composition;                 // снимок входных данных
model.pointsAt(3.4);               // [[x, y], ...]
model.pathAt(3.4);                 // открытый SVG path
model.opacityAt(3.4);              // число 0…1
model.staticSvg({ phase: .4, width: 3, background: false });
model.animatedSvg({ seconds: 1.5, width: 3, inverted: true });
```

Допустимая глубина — от 0 до `lineCount` включительно. Опция `width` в экспортерах — толщина stroke в единицах viewBox. Опция `original: true` для статичного SVG показывает все исходные линии без маски появления. Для кадра живой анимации используйте обычный `staticSvg({ phase })`.

В анимированном SVG используется SMIL с 40 интервалами на шаг, без скриптов и сетевых зависимостей. Инверсия разворачивает и геометрию, и opacity. `prefers-reduced-motion` переключает экспорт на статичную группу. Размеры корневого SVG сохраняют исходный viewBox, а обводка масштабируется вместе с композицией.

## Валидация и границы

Структура описана в `src/compositions/composition.schema.json` (JSON Schema 2020-12). Runtime-валидатор дополнительно проверяет отношения между полями, геометрию выхода, уникальность и согласованность стрелок. Неизвестные поля версии 1 отклоняются.

- 2–80 линий, 2–128 точек на путь, суммарно не более 8192 точек.
- Размер viewBox — 1–16384; координаты конечны и ограничены ±1 000 000.
- Цвета — только `#RRGGBB`; stroke — 0,25–24 единицы; opacity — 0–1.
- Шаг — 0,1–60 секунд; перспектива — 1–12.
- Все пути открытые, с `fill="none"` и настоящей обводкой.
- Экспортер экранирует заголовок и проверяет числовые параметры; JSON не может добавить исполняемый SVG-код.

`scripts/verify-compositions.mjs` проверяет исходную геометрию, конечность данных, направление стрелок, перестановку линий в обоих направлениях, SVG-экспорт и ошибки входных данных.
